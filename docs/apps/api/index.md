# API App

The REST API uses Django REST Framework with OpenAPI generated by `drf-spectacular`.
See [ADR 0006](../../arch/decisions/0006-drf-api-and-versioning.md).

## Base URLs

- `/api/v1/` — REST endpoints
- `/api/schema/` — OpenAPI document
- `/api/docs/` — Swagger UI

## Authentication

- Session authentication for browser clients.
- Token authentication (`rest_framework.authtoken`) for tools.
- Anonymous reads follow `SiteConfig.anonymous_read`; anonymous writes are rejected.

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| GET/POST | `/api/v1/pages/` | List or create pages |
| GET | `/api/v1/pages/{id}/` | Page metadata |
| DELETE | `/api/v1/pages/{id}/` | Soft-delete |
| POST | `/api/v1/pages/{id}/edit` | Create a revision |
| GET | `/api/v1/pages/{id}/revisions/` | Paginated history |
| POST | `/api/v1/pages/{id}/restore` | Restore a soft-deleted page |
| POST | `/api/v1/pages/{id}/move` | Rename, redirect or swap |
| POST | `/api/v1/pages/{id}/protect` | Set protection |
| GET | `/api/v1/revisions/{lookup}/` | Revision by revid or `p42-r7` |
| GET | `/api/v1/revisions/{lookup}/slots/` | Slot map only |
| GET | `/api/v1/titles/?title=...&namespace=0` | Resolve title/alias/redirect |
| GET | `/api/v1/titles/bindings/?title=...` | Binding history |
| POST | `/api/v1/users/{id}/block` | Create a block |
| POST | `/api/v1/users/{id}/unblock` | Lift active blocks |
| GET | `/api/v1/users/{id}/blocks/` | Block history |

Page responses include:

- `protection` — active `action → level` map
- `protections` — full structured protection rows (level, expiry, setter, reason)
- `categories` — active category titles

## Write contract

Every mutation requires `base_revid`. A mismatch returns `409 edit_conflict` and the
database is unchanged.

```json
{
  "base_revid": 12,
  "comment": "Update title",
  "slots": {
    "properties": {
      "schema": 1,
      "titles": {"primary": "Main Page", "aliases": ["Home"]}
    }
  }
}
```

The REST edit endpoint accepts `main` and/or `properties`; unchanged slots are reused.

## Error envelope

```json
{
  "error": {
    "code": "edit_conflict",
    "message": "The page changed since base_revid",
    "details": {"base_revid": 10, "current_revid": 11, "current_slug": "p7-r5"}
  }
}
```

Domain errors map to: 400 validation/title/content/block errors, 403 permission, 404
page/revision/user not found, 409 edit/title conflict or redirect loop.

## Block request

```json
{
  "reason": "vandalism",
  "expires_at": "2026-12-01T00:00:00Z",
  "autoblock": false,
  "no_create": false
}
```

`expires_at` may be `null` for an indefinite block. Past expiries, self-blocks and
blocks against deleted users return `400 invalid_block`.

## Protection request

```json
{
  "base_revid": 12,
  "protection": {"edit": "sysop", "move": "autoconfirmed"},
  "expires_at": "2026-12-01T00:00:00Z",
  "reason": "edit war"
}
```

`expires_at` applies to every action in the request. Use level `open` to remove a
protection. Every change appends a protection log row.

## MediaWiki compatibility

The `action=query/edit/move` adapter is not implemented yet. It should be a thin layer
that translates requests to the same core services; do not add MediaWiki API shapes to
the domain model.
